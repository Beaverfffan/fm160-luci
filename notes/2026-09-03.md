# 2026-09-03 工作日志

## GL-BE3600 刷入后「小屏幕全黑 + 循环启动」根因定位与修复

### 现象
用户刷入固件后：小屏幕全黑，看起来会循环启动（boot loop）。

### 硬件参数澄清（从 GL 官方/iStoreOS 权威 DTS 提取）
- SoC: IPQ5332 / AP-MI04.1-C2（官方宣传写 IPQ5312 是 SKU 差异，实测 IPQ5332）
- 内存: **512MB**（iStoreOS DTS: reg = <0x40000000 0x20000000>）
  - ⚠️ 官方宣传 1GB DDR4，但 iStoreOS（GL 官方合作版）DTS 明确写 512MB。先用 512MB 保险。
- 屏幕: 2.4" 彩色触控屏 = st7789p3 SPI 屏 + cst816s 电容触摸 + pwm-backlight
- 按键: switch=gpio35, reset=gpio36；另有 pwm-fan(风扇)、usb_power(gpio32)

### 根因 1（循环启动，致命）— 已修复 ✅
- `ipq5332.dtsi` 里 `memory@40000000` 的注释："We expect the bootloader to fill in the size"，reg size=0
- TIP 树假设 bootloader 会填充内存大小，但 GL-BE3600 原厂 uboot 不填充 → 内核看到 0 内存 → panic → watchdog 循环重启
- 修复：DTS 显式加 `memory@40000000 { reg = <0x0 0x40000000 0x0 0x20000000>; }`（512MB）
- 同时 chosen 加 `bootargs-append = " clk_ignore_unused"`（iStoreOS 也有）
- 验证：重编后 DTB 里 memory = 512MB ✅，固件已重新打包下载

### 根因 2（屏幕黑，次要）— 待后续处理
- 我们的 DTS 完全缺失屏幕硬件节点
- iStoreOS 权威节点（已提取到本地 istoreos-be3600.dts）：
  - spi@78b5000 下 st7789p3@0 (compatible="sitronix,st7789p3", width=76, height=284 横屏, te=gpio43, dc=gpio16, reset=gpio24)
  - i2c_gpio 下 cap_touch@3b (compatible="hynitron,cst816s", reg=0x15, sda=gpio34, scl=gpio33, reset=gpio37, int=gpio39)
  - backlight (pwm-backlight)
  - gl-hw 节点: screen="/dev/fb0,/dev/input/event0", noled="true", fan="hwmon0 cooling_device0"
- **关键障碍**：TIP 树 6.6 内核有 st7789v 驱动（drivers/staging/fbtft/fb_st7789v.c）但**没有 cst816s 触摸驱动**（GL 私有）
  - 屏幕要亮需：补 DTS 节点 + 移植 cst816s 触摸驱动（工作量较大）
  - 屏幕黑不影响路由功能，优先级低

### 关键工具/方法（可复用）
- 从 FIT 固件提取内嵌 DTB：Python 解析 FDT 结构，找 type="flat_dt" 节点的 data property
  - 脚本在远程 /tmp/extract_fdt.py 和 /tmp/extract_fdt2.py
- iStoreOS 固件 sysupgrade tar → kernel 文件 = FIT（含 Linux 5.4 内核 + fdt-1）
- 我们的 sysupgrade kernel = FIT（6.5MB，含 6.6 内核 + 修复后 fdt）

### 教训
- TIP wlan-ap 树的 ipq53xx DTS 依赖 bootloader 填充 memory size，第三方原厂 uboot（GL）不会填充，必须显式写 memory 节点
- 改 feeds/qca-wifi-7/ipq53xx/dts/ 下的 DTS 后，make 不会自动重编 DTB（日志无 DTS 编译记录），需删 build_dir 里的 image-*.dtb 触发重编
