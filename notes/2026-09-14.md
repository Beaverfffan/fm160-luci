### 踩坑（重要教训）
- **嵌套 heredoc 会吞掉反斜杠**：`ssh host "bash -s" <<'EOF' ... python3 - <<'PY' ... rstrip('|\\') ... PY ... EOF`
  里层的 `\\` 被外层吃掉变成 `\`，Python 报 SyntaxError。
  → 修复脚本失败后 `git cherry-pick --continue` 仍把**带冲突标记的文件**提交了（因为前面已 `git add`）。
  → **正确做法：脚本用本地 Write 落盘，再 `ssh host "python3 -" < script.py` 管道传，不要嵌套 heredoc。**
  → 且 `git add` 之后务必先 `grep` 冲突标记再 `--continue`。

### 官方流程（照做）
1. `./scripts/feeds update -a && ./scripts/feeds install -a` → rc=0
2. `cp feeds/x/rom/lede/config.<模版> .config` → 本分支有 `config.mediatek-filogic-0` / `-1`
3. `make menuconfig` 选机型 → 退出保存
4. `sh feeds/x/rom/lede/fix-config.sh`（把 CONFIG_DEFAULT_*=y 的从 m 改成 y，dnsmasq 例外）
5. 再 `make menuconfig` 退出保存
6. `make`

### 无头环境下的等价做法
x-wrt 模版是**多机型**的（-0/-1 两个模版各有 270 行 DEVICE 配置，默认编一堆机型）。
- `feeds/x/rom/lede/config.mediatek-filogic-1 .config`
- 用 python 脚本删掉所有 `CONFIG_TARGET_DEVICE[_PACKAGES]_mediatek_filogic_DEVICE_*` 行，
  只追加 `CONFIG_TARGET_DEVICE_mediatek_filogic_DEVICE_glinet_gl-be14000=y`
  （脚本 `_prepcfg.py`，本地保留在 glinet-be6500/ 目录）
- 然后 `make defconfig` → `fix-config.sh` → `make defconfig`
- 结果：`TARGET_BOARD=mediatek` + `SUBTARGET=filogic` + 唯一机型 be14000，323 个包，两个 defconfig 均 rc=0
- **关键**：不要直接照搬模版全量编译，会编 270 个机型

#### 真实错误
```
ERROR: unable to select packages:
  kmod-backlight-pwm (no such package)
  kmod-drm-panel-mipi-dbi (no such package)
```
这两个包在 BE14000 的 `DEVICE_PACKAGES` 里（blogic 提交加的），但在 x-wrt 树里根本没被构建。

#### 根因（层层递进，值得记住）
1. `.config` 里是 `# CONFIG_DISPLAY_SUPPORT is not set`
   → 这两个 kmod 在 Kconfig 里**不可见** → `make defconfig` 无从选中 → 不构建
2. 为什么是 not set：我们用的是 x-wrt 发版自带的模版 `feeds/x/rom/lede/config.mediatek-filogic-1`，
   它是**打补丁之前**生成的，把 DISPLAY_SUPPORT 显式写成了 not set；
   `make defconfig` 会保留已有的显式值，**不会**因为新加的 `default y` 而改变
3. 而 blogic 的提交 `0d9b1a7b29` 恰好就是给 `config/Config-build.in` 加了：
   ```
   config DISPLAY_SUPPORT
   	bool "Show packages that require graphics support (local or remote)"
   +	default y if TARGET_mediatek_filogic
   ```
   —— 也就是说这个 default 是**为 filogic 特意加的**，只是被旧模版压住了

#### 关键机制（纠正了我一开始的误判）
- 我一开始以为是「缺 `pwm` feature / 缺内核 CONFIG 符号」，实际都不是：
  - `CONFIG_PWM_SUPPORT=y` 本来就是 y
  - `DISPLAY_SUPPORT` 只管包的**可见性**，不等于内核符号自动开
- **DEVICE_PACKAGES 会自动把包选成 `CONFIG_PACKAGE_xxx=m`**（已用证据坐实：
  `glinet-panel-firmware=m`、`rtl8261c-firmware=m`、`bridger=m`、`kmod-input-touchscreen-cst353x=m`
  都是本次 cherry-pick 新增的包，全被自动选中）→ 选中后内核 KCONFIG 符号会自动开
- 所以**唯一缺的就是可见性**，不需要手工去改 config-6.18

#### 修复（改动极小，28 行）
```sh
sed -i '/^# CONFIG_DISPLAY_SUPPORT is not set$/d' .config
echo 'CONFIG_DISPLAY_SUPPORT=y' >> .config
make defconfig
```
结果：
```
CONFIG_DISPLAY_SUPPORT=y
CONFIG_PACKAGE_kmod-backlight-pwm=m
CONFIG_PACKAGE_kmod-drm-panel-mipi-dbi=m
```

#### 教训总结
- **用 x-wrt 官方 config 模版 + 打补丁的方式，模版里的显式 `# ... is not set` 会压住补丁新加的 `default y`**
  → 凡是补丁给 Kconfig 加了新 default 的，都要手动删掉模版里的 not set 行再 defconfig
- 排查"package 不存在"先看三件事：① 包在 `.config` 里的状态（=m/=y/not set）
  ② Kconfig 可见性（@ 依赖的 SUPPORT 符号）③ 内核 KCONFIG 符号
- 编译失败要重跑看错误时用 `tmux ... 'make <target> V=s > log'`，V=s 才会打出真实错误
