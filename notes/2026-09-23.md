### 实测记录（全部路由器实测）
- UI 语法修复：3 处 `'click'` 少开引号（node --check 不过），修后状态卡/设置卡/Save/模式切换全部渲染正常。
- **坑1（MBIM 被 QMI 代理打挂）**：QMAP 残留的 `fibo_qmimsg_server` 独占 /dev/cdc-wdm0 并向 MBIM 通道灌 QMI 报文 → 模组侧 MBIM 端点永久不应答（mbimcli open 超时），杀进程/CFUN 重启/USB 重枚举均无效，**必须 USB 模式弹跳（30→32→30）**让模组重启 USB 功能才恢复。修复：mbim-up.sh 开头杀 fibo_qmimsg_server/fibocom-dial/mbim-proxy；qmap-up.sh 开头杀 mbim-proxy（对称互斥清理）。
- **坑2（IPv6 /64 不自动跟随）**：network.fm160 是 proto none，①不产生 ifdown → LAN 前缀不收（down 主动 withdraw 解决）；②31-fm160-prefix hotplug 按接口名过滤没有 fm160 → ifup 不触发 apply（过滤加 fm160 解决）；③就算触发，ifup 时拨号 IP 还没配好 → ctl up 里 qmap 延后 50s、mbim 延后 20s 再 `fm160-prefix reload`。
- **坑3（up 阻塞超时）**：USB 切换要 30-90s，超出 LuCI 请求超时 → 前端误报「Dial failed to start: XHR request timed out」，实际后端仍在执行且最终成功。修复：onUp 改为即发即弃（catch 掉超时，提示语改为「命令已下发」，真实状态由 3s 轮询反映）。
- **坑4（切换态死锁）**：保存新模式后 usb_mode 与期望不符时按钮显示 "Switching USB profile..." 且禁用，但切换只由 up 触发 → 永远点不了 Connect。修复：该态改为可用按钮「Connect (switches USB profile first)」，只有 busy（up/down 执行中）才禁用。
- 端到端：MBIM down→up 全流程 OK（10.18.89.12 / 240e:478:1688:1499::，v4/v6 ping 通）；断开 4s 内 LAN 前缀收回；拨号 35s 内新 /64 自动上 br-lan（含前缀变更迁移）。`ubus call network.interface.fm160 status` up:true l3_device wwan0 → 网络→接口页可见。
