### 追加 §24：三协议重构为独立 luci-proto 包（09-23 09:30 用户指令「完全可以独立做三个 luci-proto-xxx-fm160」）
- 背景：用户要求三个拨号程序在「网络→接口」以原生 interface 形态可见可管理（为 mwan3 铺路），否决继续给 network.fm160(none) 打补丁。决定：三个独立包 `luci-proto-{mbim,qmi,ecm}-fm160`，各含 Makefile + `files/lib/netifd/proto/{mbim,qmi,ecm}_fm160.sh` + `htdocs/luci-static/resources/protocol/*.js`（network.registerProtocol，isFloating/isVirtual=true）。ECM 多 `usr/sbin/ecm-dhcp.sh`（udhcpc 跑 v4，模组 DHCP）。
- **netifd proto 铁律**（踩坑）：
  1. 头部必须三连 `. /lib/functions.sh` → `. /lib/netifd/netifd-proto.sh` → `init_proto "$@"`，漏 init_proto → "add_protocol: not found"，协议静默注册失败。
  2. wwan0 raw-ip 无载波 → qmi/mbim 必须 `no_device=1`；但 ecm 用 usb0（真实载波）**不能** no_device，否则 netifd 把无人认领的 usb0 拉 down。
  3. no_device 协议收不到 $2 ifname → `proto_config_add_string "device:device"` + json_get_vars 自取。
  4. proto 脚本只在 netifd 启动时扫描 → 改完必须 network restart；路由器无 /etc/init.d/netifd；别 kill netifd pid（procd crash loop）。
- dial-ctl netif_sync 映射：ecm→ecm_fm160/usb0、qmap→qmi_fm160/wwan0、mbim→mbim_fm160/wwan0；ensure 标志：33 等 /sys/class/net/usb0，30/32 等 /dev/cdc-wdm0（ECM 无 cdc-wdm0）。
- **QMAP v6 日志驱动**：fibocom-dial 守护进程反复增删地址，读网卡不可靠；以 vendor-qmap.log 的 LOGMARK（拨号前 wc -l）+ tail 取本拨号段为准，v6 地址 `ip -6 addr replace ... nodad` 自落；setup 里先 `ip link set dev $dev up` 守护进程才落 v6。
- **ECM v6 = fw4 问题**：fw4 input 默认 drop，接口不在任何 zone 时 RA 进不了内核（tcpdump 看得见、odhcp6c 收不到）。修复：netif_sync 自动把 fm160 挂进 wan zone（仅未挂任何 zone 时）；ECM proto `sysctl accept_ra=2 autoconf=1`。
- 旧单 proto fm160.sh 已删（vendor-cli/netifd-proto 目录删除 + fm160d/Makefile 移除安装行 + 构建树 rm -rf files/lib/netifd）。
