## ★ 引用约定：`存档 §NN`

`fm160-qmi/` 下的文件（含**已安装到设备上的 `usr/sbin/fm160-qmi`**，
它逐字节就是设备上跑的那一份）会引用「存档 §NN」。这个「存档」是
一份更长的开发档案 `MEMORY-FULL-ARCHIVE.md`，**不在本仓** ——
它同时包含其他设备（面板、GL-BE14000 交换机适配、GL-MT5000）的内容，
不属于本仓的范畴。

**这些引用不影响可读性**，因为对应的结论在本目录里都有：

| 存档引用 | 本仓对应位置 |
|---|---|
| §0-5（`ps\|grep` 自匹配会杀自己） | `MEMORY.md` §0 第 5 条 |
| §33.4-E（busybox `default.script` 删别人默认路由） | `2026-09-21.md` §2.3 |
| §35（`fm160-qmi` 交付与两处勘误） | `2026-09-21.md` §5 |
| §37.5（多路 PDN 未走通的两道坎） | `2026-09-21.md` §7.7 |
| §38（`.ipk` 外层必须 gzip+tar，不是 ar） | `2026-09-21.md` §7.4 |

`fm160-qmi/usr/sbin/*` 与 `etc/*` **不做任何仓库专用改写**（不改注释、
不改路径），因为它们就是要装到设备上的东西 —— 仓里的副本与设备上的
运行件必须逐字节相同，否则「仓库里的源码」就不是「在跑的程序」了。
`fm160-qmi/README.md` 没有这个问题，所以它里面的引用已改成本仓可达的路径。

## 关于设备标识

本仓是公开仓库。按既有惯例（见 `.gitignore` 里对 `_probe/` 的说明），
**真实设备标识（IMEI、序列号、SIM 标识）不入库**。本目录两个文件入库前
已逐项扫描确认：无 IMEI/序列号/token/私钥；只有实验室局域网地址
（`192.168.x.x`），与 `docs/HARDWARE-PROBE.md` 既有写法一致。
