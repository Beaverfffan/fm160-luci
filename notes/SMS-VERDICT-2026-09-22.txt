0. 问题是怎么来的
--------------------------------------------------------------------------------

  现场：NR SA 下 AT+CMGS 本地约 90~103 ms 秒拒；

    Q1 SIM 卡自己到底有没有短信业务？

1. 结论（三句话）
--------------------------------------------------------------------------------
  ① 模组**支持**短信：AT 层完整（厂商手册第 7 章 +CMGF/+CMGS/+CMGL/+CMGR/+CMGW/
     +CMGD/+CMSS），且模组自报 +CSMS: 0,1,1,1 = MO 与 MT 都支持。
  ② SIM 卡也**不是**"没有短信业务"：卡里 EF_SMSP 存着电信短信中心
     +8613344181200，与设备侧 AT+CSCA? 的原始应答两条独立来源互证一致。
  ③ ~~失败点在**承载**，不在卡、也不在 AT 命令~~  ← ★ **本条已作废**（见卷首订正）：
     实际是**模组原厂固件缺陷**，后期固件更新修复。下面的现象描述仍然有效，
     但「承载缺失」这个解释不成立。

3. 三条"对手无法伪造"的旁证
--------------------------------------------------------------------------------
  (a) 语音一样死 —— 免费对照组
      ATD10000;  → OK
      +CLCC: 2,0,2,0,0,"10000",129   ← stat=2 = dialing
      连续 28 s 采样，stat 一直是 2，**从未出现 3(alerting)**；CHUP 后 NO CARRIER。
      ⇒ 该线路上语音同样拿不到承载。数据能通、语音不能通，这是"业务面"的问题，
        不是"某一类 AT 命令没配对"的问题。
  (b) CS 域不存在
      AT+CREG? → 0,0（CS 未注册，LTE-only 下属正常）；
      CGSMS=1（要求 CS）→ 94 ms 秒拒。
      ⇒ 传统电路域短信这条路在本线路 / 本驻网状态下是关着的。
  (c) MT 侧同样为空
      收件箱 0 条（+CPMS: "ME",0,127 / AT+CMGL=4 → 空）；90 s 监听无 +CMTI；
      用户手机外部判据"没收到"。
      ⇒ 上行下行一起死，指向承载而不是方向。

  ★ 订正（读错了一次，留档防再犯）
    上一轮 out/284-decode.txt 写"EF_SST service 4 (SMS) = 2 ⇒ 2G 服务表里 SMS 有分配"。
    **这是错的。** EF_SST 每服务 2 bit：00=未分配，01=已分配，10/11=reserved。
    svc4 读到 2 = reserved，**不等于**"有分配"。该条推断作废，不再引用。

5. 关于"FM160-CN 只能走 SMS over IMS" —— 部分对，但两处必须纠正
--------------------------------------------------------------------------------
  外部资料的说法：CN 版官方规格只标 SMS over IP(IMS)，NA 版才标 SMS / IMS / NAS；
  并给了一套流程，其中"第 2 步 IMS 注册确认"要求等 +CIREGU / +VOICE REG。

  ★ 纠正一：**这个固件没有任何 IMS 状态查询命令。**
      实测（out/287-ims-discovery.json）：
        AT+CLAC         → 裸 OK（本固件不提供命令表）
        AT+CIREG?       → ERROR        AT+CIREP?       → ERROR
        AT+CIMS?        → ERROR        AT+GTIMS?       → ERROR
        AT+GTIMSSTATE?  → ERROR        AT+GTVD?        → ERROR
        AT+GTIMSEN?     → ERROR        AT+GTUICCIMS?   → ERROR
        AT+CPAS?        → ERROR   （手册 5.3.1 有定义，本固件未实现）
      厂商 130 条命令手册（_ref/fm160/docs/at/）里，唯一与 IMS 有关的 token 是 +CAVIMS。
      ⇒ 那份流程的"第 2 步"在 FM160-CN 上**无法执行**；+CIREGU / +VOICE REG 不是
        广和通的命令（是别的厂/别家的写法）。凡是"等 IMS 注册 URC"的方案都要作废。

  ★ 纠正二：**+CAVIMS 不能当"IMS 已注册"用。**
      手册原文：set 命令是"informs the MT whether the UE is currently available for
      voice calls with the IMS"，read 命令返回的是"status **stored in the MT**"。
      即它是 TE→MT 的告知 + MT 里的存量标志，不是实时注册状态。
      `+CAVIMS: 1` 只是说"MT 里记着 IMS 语音可用"，与本次失败不矛盾。

  ★ 还有一条**反证**，"IMS-only"不足以解释全部现象：
      若短信只走 IMS，那么在同一个"IMS 未注册"的状态下，NR SA 与 LTE 的表现应当相同。
      实测却是：NR SA 90~103 ms **本地秒拒** vs LTE 提交后**等满 40 s**。
      这个不对称说明 LTE 那一次走的是**一条非 IMS 的承载**（NAS/SGs 类），
      否则它也会在本地秒拒。⇒ 不能断言"CN 版只能走 IMS"。
      （能确定的是：CN 版**确实**有 IMS 栈 —— 官方中文站写明 FM160-CN 支持 VoNR，
        而 VoNR 必须走 IMS；手册也警告"不要改 IMS 与 SOS APN，否则 UE 无法注册 IMS"。）


6. 剩下的两个候选根因 + 各自唯一的判别实验
   ★★ 整个第 6 节已作废（H1/H2 两个假设都不成立，根因是原厂固件缺陷）。
      保留原文仅作「当时的推理路径」留档；E1/E2 不必再跑。
--------------------------------------------------------------------------------
  H1  承载缺失：模组没把 IMS 那条 PDP 拉起来
      证据（本轮新增，模组自己的视图）
        AT+CGACT?        → 1,1  2,0  3,0 …      ← 只有 ctnet 激活，ims(cid2) 没起
        AT+CGPADDR=2     → +CGPADDR: 2,"0.0.0.0"
        AT+CGCONTRDP=2   → ERROR（没有动态参数）
        AT+GTMPDN?       → +GTMPDN: 0            ← VLAN 多路 PDN 关闭
        AT+GTWWAN?       → +GTWWAN: 1,1,"10.37.80.55,240e:478:16a8:1189:b9a2:6c26:fcde:a81a",…
        AT+GTRNDIS?      → 只有 cid 1 一路
      参照（厂商自己的 ECM 样例，_ref/fm160/docs/Dialup-ECM-NCM-RNDIS-MBIM.txt:860）
        +CGDCONT: 2,"IPV4V6","ims","0.0.0.0,36.9.129.112.10.60.154.221.22.182.108.159.217.500
        ⇒ 厂商样例里 ims 那条 **带着真实 IPv6 地址**（移动 2409: 段）；
          我们这条是 "IP"（仅 v4）且 0.0.0.0 ⇒ 明显不同。
      判别实验 E1（本地，可回滚，不花短信额度）
        AT+CGACT=1,2  然后看 AT+CGPADDR=2
          拿到地址 ⇒ 网络允许 IMS PDN，问题在"模组/剖面没去拨它" ⇒ 落在 H1
          ERROR    ⇒ 这条线路根本没给 IMS 承载          ⇒ 倾向 H2
        回滚：AT+CGACT=0,2

  H2  网络侧停掉了这条线路的短信/语音
      证据：数据面全通（ECM v4 10.37.80.55 / v6 240e:478:… 都通，DNS 218.2.2.2 正常）；
            而语音与短信**同时**不通，且上行下行都不通。
      判别实验 E2（外部判据，免费，最强）
        **把这张卡插进手机，用手机试发一条短信 + 打一个电话。**
          通   ⇒ 卡与线路没问题 ⇒ 问题在模组侧（H1 方向），继续修模组
          不通 ⇒ 这条线路本身没有短信/语音业务 ⇒ 与模组无关，本问题收口
